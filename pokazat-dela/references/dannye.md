# Данные дашборда

Python 3, без зависимостей. Пути относительно проекта, не могут выходить из него.
Помощник заполняет конфиг из реальных источников; шаблон не содержит достижений.

```json
{
  "title": "Моя команда",
  "journal": "zhurnal.md",
  "steps": ["Подготовка", "Результат"],
  "actors": ["Подготовщик", "Автор", "Проверяющий"],
  "scope_version": "uchastok-1",
  "live": false,
  "cases": [],
  "attempts": []
}
```

cases: все известные номера дел строками. attempts: запись на каждую попытку:

```json
{
  "id": "baseline-01",
  "case": "01",
  "series": "baseline",
  "scope_version": "uchastok-1",
  "input_hash": "sha256:вычисленная-сумма-неизменного-входа",
  "synthetic": true,
  "observed": false,
  "touches_known": false,
  "result": "dela/01/baseline-01/result.md",
  "check": "dela/01/baseline-01/check.md"
}
```

series: trial / baseline / repeat / other. id уникален, латиница/цифры/дефис/подчёркивание.
observed=true только после завершения либо остановки с зафиксированным итогом; это
не успех. touches_known=true только если действительно записаны все ручные действия,
не автоматически по отсутствию «я». В режиме Б ручные передачи записываются обязательно.
input_hash вычисляется по неизменным входным файлам в стабильном порядке, повтор
использует точные копии, а не ответы прошлой серии. Изменился участок: новая
scope_version. Неизвестную сумму оставь пустой, сравнение будет недоступно.

Учебный пример строк (не подставлять в проект):

```text
когда | дело | шаг | кто | исход | примечание
2026-09-16T10:00:00+03:00 | 01 | Подготовка | Подготовщик | начал | run=baseline-01;
2026-09-16T10:01:00+03:00 | 01 | Подготовка | Подготовщик | готово | run=baseline-01; проверены поля
2026-09-16T10:02:00+03:00 | 01 | Подготовка→Результат | я | готово | run=baseline-01; открыл следующий чат и приложил файл
```

В Markdown экранируй | в тексте как \|. Дубли идентичных строк пропускаются с
предупреждением. Журнал append-only. Неизвестный шаг, исход, автор, номер дела или
попытки делает оценку неопределённой. actors содержит подтверждённые имена ролей,
«я» распознаётся отдельно. Без run строка показывается как нераспределённая.

Для последнего шага нужны «готово», затем «принято», существующие result и check
этой попытки. После нового «начал», отказа, исправления или отклонения прежняя
приёмка устаревает: нужны новое завершение и проверка. Скрипт не проверяет смысл
файла: перед «принято» проверяющий читает результат и критерии договора.

Учебные прогоны не повторяют отправки, публикации, заказы. Только локальные копии,
внешний эффект заменяется явно подписанной заглушкой. Это не тест реальной интеграции.

Без скрипта используй те же правила и структуру D в шаблоне. В JSON для script
заменяй < на \u003c, чтобы данные не становились HTML. Ручной HTML-снимок:
mode="снимок по загруженным данным", live=false. Браузер не читает папку сам.

## Выходной JSON для ручного снимка

Вставляется внутрь script#dannye вместо null. Пример пустого экрана:

```json
{
  "title": "Команда", "live": false, "mode": "снимок по загруженным данным",
  "updated": "фактическое время с часовым поясом", "source": "имя загруженного журнала",
  "steps": [], "attempts": [], "series": {},
  "comparison": {"comparable": false, "delta": null},
  "warnings": [], "unassigned": [], "cases_without_journal": []
}
```

Для каждой попытки в attempts: id, case, series, synthetic, observed, complete,
no_hands, touches_known, touches, data_errors, tool_errors, acceptance (последнее
принято/поправил/отклонил либо null), uncertain, problems (массив пояснений), cells.
В cells по одному объекту на шаг: step, state (net/idet/vstalo/proshlo), touches,
reworks. Все числа только из журнала. series: ключи trial/baseline/repeat/other,
значения {total, observed, complete, no_hands}. Нет учёта касаний: touches_known=false,
no_hands=false, пояснение в problems. Не смешивай «не подтверждено» и реальный ноль.
В warnings включи число нераспределённых строк; в cases_without_journal номера дел.
Таблица в чате использует те же показатели, без необходимости формировать JSON.
