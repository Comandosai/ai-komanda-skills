Где работает команда и что именно переносится

Проверка документации: 22.09.2026. Название модели не описывает всю среду. Gemini в браузере и Gemini CLI различаются; Claude в чате, Cowork и Claude Code не равнозначны. Сначала помощник проверяет доступные файлы, инструменты и запуск независимых исполнителей, затем выбирает адаптер.

Общий принцип

Паспорта в agenty/ и навыки остаются каноническими документами. Карточка платформы содержит метаданные и ссылку на паспорт, а не вторую полную копию бизнес-инструкции. Изменения паспорта проверяются пробным запуском. Файл Markdown не является работающим агентом до запуска исполнителем.

Неизвестная возможность означает «нужно проверить», не «эта платформа ничего не умеет». Наличие кнопки расписания не доказывает доступ к локальной папке или дочерним исполнителям.

Claude Code

Документированный механизм: .claude/agents/*.md внутри проекта, управление через /agents. Отдельный subagent имеет собственный контекст и набор инструментов. Настройку создаёт помощник по актуальному формату, даёт минимальные необходимые права и ссылку на паспорт.

Проверка участника:

1. Открыть нужный проект в Claude Code.

2. Проверить через /agents, что карточки доступны.

3. Попросить диспетчера показать выбранную роль и вход.

4. Запустить одно пробное дело и проверить, что действительно был вызван исполнитель, а не только написано его имя.

5. Проверить, что проверяющий получил исходник и критерии, не только вывод автора.

Не включаем обход разрешений ради отсутствия остановок. Модель и доступы выбираются осознанно; более дешёвую модель проверяем на той же задаче по качеству, а не по названию. Эти карточки не являются автоматически работающей настройкой обычного Claude-чата или Cowork.

Источник: Claude Code custom subagents.

Gemini CLI

Текущая документация описывает встроенных и пользовательских subagents. Проектные карточки находятся в .gemini/agents/*.md, пользовательские в ~/.gemini/agents/*.md. Поэтому старое общее утверждение «Gemini не умеет связывать роли» использовать нельзя.

Помощник сначала сверяет установленную версию и доступность механизма. Затем создаёт тонкие карточки с корректным frontmatter и доступными именно в этой версии именами инструментов. Явное обращение к агенту поддерживается через @имя. Проверяем фактический вызов и результат.

Gemini в браузере и Antigravity отдельно проверяются по доступным инструментам. Нельзя переносить на них настройки CLI только из-за общего бренда или выбранной модели.

Источник: Gemini CLI subagents.

Codex

Официальная документация на 22.09.2026 описывает пользовательских исполнителей

в .codex/agents/*.toml. Старое утверждение «у Codex нет карточек» больше не используем.

Минимальный пример для помощника, только после проверки версии и существующего паспорта:

name = "analitik"
description = "Выполнить шаг анализа по паспорту проекта"
developer_instructions = "Прочитай agenty/analitik.md относительно проекта. Выполни назначенный шаг и его проверку. Дело, попытку и вход возьми из задания диспетчера."

Подставляются реальные имя и путь. Модель и ограничения инструментов выбираются

по установленной версии и правам задачи, не копируются слепо из чужого проекта.

AGENTS.md содержит короткую ссылку на agenty/dispetcher.md для команды запуска,

а не копии всех паспортов. После настройки откройте новый чат проекта, запустите

пробное дело и проверьте фактический вызов исполнителя, файл результата и проверку.

Локальное расписание требует включённого компьютера и работающего приложения.

Облачные задачи используют доступный им контекст и подключения, не получают

автоматически папку с рабочего стола. Доступность зависит от среды и настроек аккаунта.

Проверяйте место исполнения, права и результат реального срабатывания.

Источники: Codex subagents,

scheduled tasks.

Обычный чат ChatGPT, Gemini или Claude

Консервативный ручной маршрут остаётся рабочим, если среда позволяет читать приложенные материалы и выдавать требуемый результат:

1. Приложить актуальные правила, паспорт нужной роли, нужные навыки и вход конкретного дела.

2. Запустить роль в новом чате.

3. Скачать результат и проверку; сохранить в папку соответствующего дела и попытки.

4. Приложить следующей роли актуальный результат, её инструкции и критерии в новом чате.

5. Записать ручную передачу как касание.

Если чат не может создать файл нужного формата, запустить скрипт или прочитать необходимые данные, это явный блокер. Не имитируем выполнение скрипта текстом. Такой маршрут не называется автономной командой и не обещает работу 24/7 с локальной папкой. Для одного запуска без ручных передач выбирается доступная исполнительная среда, например проверенный CLI/Hermes. Переход не заставляет заново придумывать роли.

Hermes на компьютере или VPS

Передаются папка и правила, затем настраивается исполнение. Передача Hermes и установка на VPS описывают конкретный маршрут. Важны три отдельных проверки: CLI из каталога проекта, gateway с terminal.cwd, cron с --workdir. Учебная конфигурация использует один профиль default и одного владельца.

Источник: Hermes configuration.

Что не переносится само

Ключи и OAuth, browser-сессии, MCP-подключения, Windows-программы, корпоративная сеть, разрешения файлов, переменные окружения и подписка пользователя. Для каждой зависимости в инструкции передачи указываем: где получить, кто разрешает, как проверить. Если перемещается только папка, пишем «папка передана»; «команда перенесена» только после проверенного сквозного запуска.

Минимальная проверка любой среды

  • Читает текущие, а не старые приложенные файлы.
  • Может создать фактический результат требуемого формата.
  • Проверка имеет доступ к исходникам.
  • Независимые роли действительно исполняются независимо, если это заявлено.
  • Есть устойчивое место результатов и журнала.
  • Ограничения и ручные передачи отражены честно.
  • Автозапуск проверен с закрытым пользовательским чатом, если обещан.

В этой инструкции проверены документированные механизмы Claude Code, Gemini CLI и Hermes. Не выполнены установки и бизнес-прогоны во всех перечисленных продуктах. Ручной маршрут является безопасным ограниченным вариантом, а не утверждением о полном наборе функций любого тарифа.
