# Команда на VPS: Ubuntu и Hermes

Проверка документации: 22 сентября 2026. Команды ниже сверены с официальными источниками. На чужом сервере ничего не устанавливалось. Перед записью ведущий выполняет контрольный запуск на выделенном учебном VPS и фиксирует версию. Это инструкция для выбранного маршрута, не обещание совместимости любого проекта.

## Что получится

Папка команды находится на сервере. Hermes читает диспетчера, запускает рабочий маршрут и сохраняет результаты. Gateway работает как служба, поэтому закрытие SSH и выключение ноутбука не должны останавливать расписание. VPS является компьютером; Hermes является исполнителем. Для работы нужны оба, а также доступ к выбранной модели.

Учебный маршрут: отдельный VPS с Ubuntu 24.04 LTS, один пользователь `team`, один профиль Hermes `default`, один проект `/home/team/projects/ai-komanda`. Для начала выбирайте небольшой тариф с возможностью увеличения ресурсов; требования браузера и файлов могут быть существенно выше простого текстового процесса. Конкретный тариф утверждаем после измерения демонстрационного проекта, не называем его универсальным минимумом.

## 0. До покупки и подключения

- Уточните доступность выбранного провайдера модели из региона сервера, способы оплаты и правила обработки данных.
- Сервер оплачивается отдельно от модели и сервисов. Подписка на чат не означает автоматически API-доступ или право безлимитной серверной работы.
- Если проект требует Windows Excel, локального принтера, закрытой сетевой папки или корпоративного сертификата, остановитесь и согласуйте архитектуру. Linux VPS не переносит эти возможности сам.
- Для 1С на компьютере с запретом установки ИИ используйте разрешённую выгрузку или интеграцию через администратора. Не обходите запрет.
- Подготовьте чистый комплект команды без ключей и персональных данных для первой проверки. Убедитесь, что диспетчер уже проверен локально.
- Запишите владельца сервера, ответственного за оплату, резервные копии и обновления.

## 1. Два окна терминала

На своём компьютере откройте терминал. `SERVER_IP` далее замените на адрес своего VPS. Значения в угловых скобках из примеров не вставляйте буквально.

Если SSH-ключа для учебного сервера ещё нет:

```bash
ssh-keygen -t ed25519
```

При запросе имени укажите новый файл, например `~/.ssh/ai-komanda-vps`. Не перезаписывайте существующий ключ. Поставьте пароль на приватный ключ. В панель хостинга добавляется только файл с окончанием `.pub`. Приватный файл никуда не пересылается.

Первый вход через учётную запись, которую выдал провайдер. Если это root:

```bash
ssh -i ~/.ssh/ai-komanda-vps root@SERVER_IP
```

При первом подключении сверьте отпечаток сервера с панелью/консолью хостинга. Не отключайте проверку host key. Если хостинг выдал другого административного пользователя, используйте его и `sudo` для административных команд.

В серверном окне администратора:

```bash
apt update
apt install git curl xz-utils rsync nano
adduser team
```

Создайте пользовательский доступ через публичный ключ. Если парольный SSH разрешён, на своём компьютере:

```bash
ssh-copy-id -i ~/.ssh/ai-komanda-vps.pub team@SERVER_IP
ssh -i ~/.ssh/ai-komanda-vps team@SERVER_IP
```

Если `ssh-copy-id` отсутствует или парольный вход выключен, попросите администратора добавить публичный ключ в `/home/team/.ssh/authorized_keys` с владельцем `team`, правами `700` на `.ssh` и `600` на `authorized_keys`. Приватный ключ для этого не нужен.

Второе окно должно успешно войти как `team`. Проверка:

```bash
whoami
pwd
```

Ожидаем `team` и `/home/team`. Не закрывайте административную сессию до проверки. Не выдавайте агенту root и не добавляйте `team` в sudo без отдельной необходимости. Входящие порты: для этого урока нужен SSH; публичная панель и открытый webhook не нужны. Ограничьте SSH своим адресом в firewall хостинга, сохранив аварийную консоль.

## 2. Установка без слепого запуска скачанного кода

Все дальнейшие команды, кроме явно отмеченных административных, выполняются в серверном окне `team`.

```bash
mkdir -p /home/team/install-review
curl -fL https://hermes-agent.nousresearch.com/install.sh -o /home/team/install-review/hermes-install.sh
sha256sum /home/team/install-review/hermes-install.sh
less /home/team/install-review/hermes-install.sh
```

`q` закрывает просмотр. Попросите технического помощника проверить установщик, источники загрузки и ожидаемые изменения. Контрольная сумма фиксирует просмотренный файл, но сама по себе не доказывает доверие к нему. После проверки:

```bash
bash /home/team/install-review/hermes-install.sh --skip-browser --skip-computer-use
source /home/team/.bashrc
hermes --help
hermes doctor
```

Сначала ставим без браузера. Если процесс требует его, устанавливаем отдельно по текущей документации: системные библиотеки устанавливает администратор, браузер и профиль принадлежат `team`. Не запускайте браузер с доступами владельца без согласования. Установщик Hermes устанавливает необходимые языковые зависимости; отдельные библиотеки конкретных навыков проверяются дополнительно.

Если `hermes` не найден, проверьте `/home/team/.local/bin/hermes --help`. Не запускайте исходный Python-файл вместо установленного launcher.

Зафиксируйте версию исходников для видео и отчёта:

```bash
git -C /home/team/.hermes/hermes-agent rev-parse HEAD
```

## 3. Модель, ключи и предел расходов

```bash
hermes model
hermes tools
```

В мастере выбираем провайдера, доступную модель и вводим ключ скрытым способом. На записи скрываем ввод и страницы личного кабинета. Инструменты включаем только нужные: файловые операции, терминал, делегирование для диспетчера при необходимости. Отдельно проверяем набор инструментов для `cron`, он может отличаться от интерактивного чата.

Секреты Hermes хранятся в `/home/team/.hermes/.env`, настройки в `config.yaml`. Не копируйте целиком `.hermes` в пакет команды. Для дополнительного API используйте приватный редактор, не строку команды с ключом:

```bash
umask 077
nano /home/team/.hermes/.env
chmod 600 /home/team/.hermes/.env
```

Добавьте только имена и значения, которые требует проверенный адаптер, сохранив существующие строки. Пример имени: `MY_SERVICE_API_KEY`; название из примера не является настройкой конкретного сервиса. В проекте сохраняются только имена необходимых переменных и инструкция получения. Файл `.env` не надо показывать агенту или выводить через `cat`.

В кабинете провайдера установите жёсткий лимит расходов, если доступен, и уведомления. В Hermes для учебного запуска:

```bash
hermes config set agent.max_turns 30
hermes config set cron.max_parallel_jobs 1
```

30 итераций является стартовым учебным ограничением, не гарантией завершения и не денежным лимитом. Проверяйте счёт провайдера. Если лимит оборвал дело, результат не становится готовым. Не повышайте лимит бесконечно вместо исправления цикла.

## 4. Переносим подготовленный комплект

На сервере:

```bash
mkdir -p /home/team/projects/ai-komanda
```

На своём компьютере, только после проверки экспортной папки на секреты:

```bash
scp -i ~/.ssh/ai-komanda-vps -r /ABSOLUTE/PATH/ai-komanda-export/. team@SERVER_IP:/home/team/projects/ai-komanda/
```

`/ABSOLUTE/PATH/ai-komanda-export` замените на реальный путь чистого экспорта. Это не рабочая папка с ключами и историей клиентов. Для повторной передачи сначала отдельная резервная копия, затем сравнение; не затирайте серверные результаты старой локальной копией.

На сервере:

```bash
cd /home/team/projects/ai-komanda
ls -la
hermes config set terminal.cwd /home/team/projects/ai-komanda
hermes
```

Первое сообщение:

> Прочитай правила этого проекта и agenty/dispetcher.md. Проверь наличие входов, навыков, инструментов и проверок. Пока не запускай расписание и не отправляй ничего наружу. Покажи, что переносится без изменений, какие пути и зависимости требуют настройки. Не читай значения секретов: проверь только наличие доступа безопасным тестом.

Если паспорт находится по другому пути, подставьте найденный путь. Исправляются ссылки и адаптер исполнения, не переписывается бизнес-процесс. Проверяющий должен видеть исходные данные, а не только резюме автора. Если независимые исполнители недоступны, не объявляем обычный единый чат эквивалентом.

## 5. Ручное дело на сервере

В свежем сеансе Hermes из папки проекта:

> Запусти всю команду. Пробный прогон. Вход: [точный путь тестового комплекта]. Ничего не публикуй; используй согласованный тестовый режим.

Проверьте фактические файлы результата и проверки, запись в журнале, отдельную папку попытки, правильное дело и остановки. Успешная установка Hermes ещё не является успешным переносом команды.

## 6. Gateway и работа после выхода из SSH

Для уведомлений своему Telegram сначала выполните:

```bash
hermes gateway setup
```

Мастер настраивает токен бота и разрешённых пользователей. Для учебного бота разрешите только свой идентификатор. Никогда не открывайте доступ всем к боту с терминалом. Выдайте тестовое сообщение и проверьте, что посторонний пользователь не получает доступ. Публичное сообщество не является административным чатом бота.

Для работы расписания без мессенджера gateway также нужен. Под `team`:

```bash
hermes gateway install
hermes gateway start
hermes gateway status
```

В административном окне:

```bash
loginctl enable-linger team
loginctl show-user team -p Linger
```

Ожидаем `Linger=yes`. Без lingering пользовательская служба может не пережить выход и не запуститься после загрузки. Не запускайте одновременно ручной `hermes gateway` и установленную службу.

## 7. Безопасная первая задача по расписанию

В новом терминале `team` проверьте синтаксис установленной версии:

```bash
hermes cron create --help
hermes cron list
```

Создаём сначала приостановленную задачу. Это проверка подключения проекта, не повторная обработка бизнес-дела:

```bash
hermes cron create "every 1h" "Прочитай agenty/dispetcher.md в текущем проекте. Только проверь наличие указанных входов и инструкций. Не выполняй дело, не меняй файлы команды и не отправляй сообщения наружу. Верни краткий статус и перечень недостающего." --workdir /home/team/projects/ai-komanda --name week6-canary --paused
hermes cron list
```

Скопируйте точный ID задачи из списка:

```bash
hermes cron run JOB_ID
hermes cron list
```

`JOB_ID` заменяется реальным ID. Ручной запуск может обходить паузу и зависит от версии по синхронности: подтвердите завершение в статусе, а не по возврату команды. Выходы задач: `/home/team/.hermes/cron/output/<job_id>/`. Читайте только соответствующий файл, проверьте его перед отправкой наставнику.

**Критично:** у cron должен быть `--workdir`. Без него проектные правила могут не загрузиться, даже если в gateway настроен `terminal.cwd`.

После успешной проверки замените задачу через помощника на ваш действительный маршрут. Текст для Hermes:

> Настрой одну приостановленную задачу для этого проекта. Запуск [условие и часовой пояс]. В каждом запуске обрабатывай не более одного нового полного дела по agenty/dispetcher.md. Перед запуском проверь журнал, статус и блокировку дела. Повтор события не должен повторять внешнее действие. При отсутствии нового входа ничего не генерируй. При ожидании согласования сохрани состояние и уведомь только меня. Покажи ID, абсолютный workdir, расписание с часовым поясом, модель, инструменты и получателя. Не включай до моего согласия.

Проверьте созданное описание и ближайшее время в `hermes cron list`. На уровне процесса нужны атомарный захват дела и устойчивый ключ внешней операции; фраза «не повторяй» не заменяет их. Если адаптер не умеет защищать внешние действия, оставьте отправку ручной. Один параллельный cron не защищает от одновременного ручного запуска.

Включение выбранной задачи:

```bash
hermes cron resume JOB_ID
hermes cron list
```

Не используйте в расписании «продолжи как выше»: каждый запуск получает свежий контекст. Не создавайте отдельные временные cron-задачи на каждую роль: один диспетчер обязан дождаться проверенного выхода предыдущей.

## 8. Доказательство автономности

1. Оставьте один безопасный новый вход.
2. Запишите ожидаемое время и номер дела.
3. Выйдите из SSH командой `exit`, закройте рабочую сессию ноутбука.
4. После срока войдите снова и проверьте `hermes gateway status`, `hermes cron list`, файлы результата и журнал.
5. Подтвердите именно новый запуск, не старый файл и не только уведомление.
6. Отдельно проверьте после согласованной перезагрузки учебного сервера. Не перезагружайте чужую рабочую машину.

Если делается три финальных дела недели 6 на VPS, этот запуск может быть одним из трёх. Не добавляйте ещё пять только ради сервера.

## 9. Пауза, ошибки и обновление

```bash
hermes cron pause JOB_ID
hermes gateway status
hermes doctor
hermes cron list
```

Пауза предотвращает новые автоматические запуски, но не гарантирует прекращение уже выполняющегося дела. Для текущего сообщения в мессенджере есть `/stop`. Аварийная остановка всей службы:

```bash
hermes gateway stop
```

После принудительной остановки проверьте незавершённые дела и внешний сервис до повтора: запрос мог успеть выполнить действие. Для восстановления:

```bash
hermes gateway start
hermes gateway status
```

Логи находятся в `/home/team/.hermes/logs/`, выход конкретного расписания в `cron/output/<job_id>/`. Ошибка исполнения и ошибка доставки уведомления разные: не запускайте дело заново только потому, что Telegram не получил результат. Если процесс не запускался вообще, проверьте службу, расписание, часовой пояс, профиль и права.

Перед обновлением: пауза задач, завершение текущего дела, защищённая резервная копия проекта и состояния, фиксация версии. Затем `hermes update` и повтор контрольного дела. Не обновляйте прямо перед демонстрацией. Резервная копия `.hermes` содержит секреты и историю, её нельзя публиковать.
