# Комплект недели 6

Открыть GUIDE-N6.html. Полный архив участника: downloads/AI-KOMANDA-N6.zip.
Рабочие папки недели 5 не заменять. Материалы помещаются в materialy-nedeli-6.

## Результат недели

Участник не просто делает три прогона. Он проходит полный маршрут из девяти блоков:

1. безопасно добавляет материалы недели 6 и связывает существующие роли;
2. проводит два пробных дела и сохраняет обобщаемые уроки;
3. подключает одну реальную передачу и определяет триггер;
4. разбирает журнал с механиком и проверяет одобренные улучшения;
5. проводит три финальных дела; при работающем подключении использует его данные;
6. сначала копирует рабочую папку, затем очищает и упаковывает только копию;
7. продолжает в исходном проекте либо принимает копию у человека, на VPS или в Hermes;
8. настраивает рабочий триггер и отдельный регулярный цикл механика;
9. одним запуском навыка `otchet` получает `OTCHET-N6.md` и
   `PREZENTACIYA-HAKATON.html`.

Участник открывает ту же рабочую папку, в которой проходил недели 1–5. Первый
промпт получает комплект, добавляет svyazat-komandu и обновляет mehanik и otchet,
сохраняя доработки. Инструкция установки: instructions/USTANOVKA.md.
NEDELYA-6.md в проекте фиксирует фактические пути и состояние; каждый следующий
промпт читает его. Чат-копии сохранены в архиве как запасной формат, но не являются
основным маршрутом гайда. Методология сборки следующей команды в этот комплект
не входит: для неё будет отдельный навык.

## Состав

- content.json: единственный источник шагов, хронометража, ожидаемых файлов и
  промптов; GUIDE-N6.html и prompts.json генерируются.
- instructions/: подробные API/извлечение, перенос на VPS, отдельный маршрут Hermes, платформы; рядом HTML-копии для браузера.
- assets/shablon-hakatona.html: утверждённый светлый шаблон защиты;
  демонстрационный блок данных обязательно заменяется через
  scripts/render_hackathon.py. Официальный знак лежит в
  assets/comandos-logo.png и при сборке встраивается внутрь автономного HTML.
- demo/final-report/dannye-prezentacii.json: только пример структуры данных, не
  значения для реальной сдачи.
- scripts/: сборка страниц, нового снимка учёта, архива и проверки.
- demo/: детерминированный симулятор отдельно от живого учебного проекта.
- recording/: сценарии видео и контрольная проверка перед съёмкой.
- PROVERKA.md: факты тестирования и оставшиеся внешние проверки.

Материалы недели 6 добавляются рядом с прежними, а не поверх них. При совпадении
имён сначала нужна резервная копия и сравнение. Упаковка команды также не меняет
оригинал: источник копируется целиком, и только новая копия очищается от дел,
данных, секретов, кэша и абсолютных путей.

## Сборка

Из корня репозитория:

```bash
node scripts/sync-week5-chat.mjs
python3 week6/scripts/build_kit.py
python3 -m unittest discover -s week6/tests -v
python3 -m unittest discover -s week6/demo -p 'test_*.py' -v
python3 tests/test_week5.py
node tests/test-render.mjs
python3 week6/scripts/package_kit.py
```

Новый экран недели 6 не меняет старый build_dashboard.py. Читает только новый
dashboard/week6.json, пишет DASHBOARD-N6.html. Сам наличие файлов не доказывает
качество или реальность автономного запуска.

Публикация GitHub отдельно: архив локален до явной проверки версии и публикации.
Не выдавать существующую ссылку main за ссылку на ещё не опубликованный комплект.
