# Проверки комплекта недели 5

Дата: 16.09.2026. Это протокол локальных проверок, не сертификат работы всех моделей
и приложений. Данные вымышлены; реальные файлы и личные данные участников не включены.

## Воспроизводимые проверки

```sh
python3 -m unittest discover -s tests -v
node tests/test-render.mjs
node scripts/sync-week5-chat.mjs
git diff --check
```

Python: 21 тест, включая 6 подслучаев форм процессов. Проверены нулевой экран,
обязательные шаги и проверка, ручная передача, одновременное касание и переделка,
остановки по данным/инструменту, устаревшая приёмка после перезапуска или отказа,
перезапуск предыдущего шага, неизвестные касания/авторы, дубли, старые строки без
меток, две сопоставимые пятёрки, изменившиеся входы, повторное использование старого
результата, экранирование HTML и разделителя, уникальные снимки, выход пути за проект.

Node: исполнение кода HTML на минимальной модели DOM, нулевой/заполненный экран,
экранирование, соответствие семи текстов кнопкам копирования, точное совпадение
четырёх чат-инструкций с каноном и двух шаблонов, наличие вложенных инструкций.
Это НЕ визуальная проверка браузером и НЕ реальное нажатие семи кнопок.
Четыре изменённых навыка дополнительно проверяются валидатором формата SKILL.md.

## Сценарный разбор по типам работ участников

| Сценарий | Риск | Что должно происходить |
|---|---|---|
| Снабженец → сметчик | Разные имена файлов, потерянные идентификаторы строк | Сначала схема и вопросы; согласовать точные поля; при отсутствующем поле остановка, а не выдуманная смета |
| Ozon: размещение и хранение | Роли относятся к разным процессам; API недоступен | Не соединять по факту наличия двух паспортов; определить участок, отсутствие источника отметить |
| План БТИ → КП | Адрес требует подтверждения человека | Сохранить границу; завершение с человеком не назвать «без рук» |
| Подготовка → автор блога | Автор нанят раньше подготовщика | Порядок из карты процесса, не из очереди создания ролей |
| Производственный дашборд → аналитик смены | Уже работающий договор | Не перестраивать без нужды; проверить передачу и сравнить одинаковые входы |
| Один технолог | Нет второго сотрудника | Не выдумывать вторую роль; измерять доступный участок и явно отметить отсутствие проверки |
| Ядро контента → согласование → материалы | Согласование пропускается ради автоматизации | Сохранить человека, остановиться до ответа; публикацию не выполнять без разрешения |

Часть «поддерживает ли модель правильный разговор и соблюдает ли навык» проверена
чтением инструкций и сценарием, не независимым исполнением другой моделью. Скриптовые
тесты воспроизводят события и вычисления, а не доказывают следование LLM инструкциям.

## Финальное интервью: контроль сценариев

- Участник сразу назвал источник, конкретные данные и получателя: три темы закрыты,
  повторять их нельзя. Следующий вопрос только о ещё неизвестном запуске/помощи.
- «Хочу 1С, не понимаю что значит какие данные»: коротко объяснить на его процессе,
  спросить про остатки/заказы/другие нужные данные, не просить API и пароль.
- «Пока не знаю, где запускать»: принять неопределённость, не навязывать VPS.
- «Ничего не получилось, могу сдать?»: собрать фактический неполный отчёт, не
  дорисовывать пять прогонов, выяснить главную нужную помощь.
- Все темы уже отвечены в чате: только резюме для поправок, без нового интервью.
- Пожелания к интеграциям не видны: не притворяться, что видел прошлый разговор.
- Спросили неделю 5 при установленном старом otchet: обновлённый маршрутизатор
  читает только инструкцию N5, не навязывает пять вопросов и структуру недели 3.

## Что остаётся проверить живьём

- Загрузку карточек и работу отдельных исполнителей в конкретных версиях Claude
  Code, Codex, Gemini CLI. Документированные форматы приведены, но создание примера
  TOML/Markdown не является проверенным запуском агента.
- Интервью и весь процесс на реальном обезличенном проекте участника в каждой среде.
- Визуальную вёрстку, кнопки копирования и цикл обновления вкладки в браузере.
  В текущем сеансе доступ браузерного инструмента к локальному файлу был заблокирован;
  обход ограничений не использовался. Статические и офлайн-JS проверки пройдены.
- Независимых испытателей через навык orchestration: Orca не запущена, штатный
  `orca open --json` вернул runtime_open_failed. Подмена другим механизмом запрещена
  этим навыком. Поэтому независимые агентные тесты не заявляются выполненными.

В обычном чате без исполнителей предусмотрены А/Б и снимки, а не обещание фоновой
автоматизации. VPS, расписание и реальные интеграции здесь не устанавливаются.
