# Безопасная репетиция недели 6

Для настоящей работы ИИ используйте отдельную исходную папку [live-project](live-project/README.md).
В ней есть паспорта, навыки, справочник и вымышленные заявки, но намеренно нет
готового диспетчера. Этот симулятор не заменяет живую демонстрацию.

Это детерминированный офлайн-симулятор файловых переходов. Он НЕ вызывает ИИ,
НЕ создаёт настоящих агентов, НЕ подключает сервисы, НЕ публикует, НЕ доказывает
автономную работу или качество текстов. Данные вымышленные. Результаты этого
симулятора нельзя выдавать за зачётные дела участника или замеры экономии.

Назначение: проверить понятность демонстрации, отдельные папки попыток,
сохранность истории, остановки и перепроверку зависимых файлов. Журнал здесь
собственный учебный. Его нельзя импортировать в дашборд недели 5 как рабочие данные.

## Проверка

Из корня репозитория:

```sh
python3 -m unittest discover -s week6/demo -p 'test_*.py' -v
```

## Первая репетиция

Создайте отдельную временную папку. Не используйте проект участника:

```sh
demo_output=$(mktemp -d)
python3 week6/demo/simulator.py --input week6/demo/cases/trial-1.json --output "$demo_output" --attempt trial-1 --roles 2
```

Путь напечатайте командой `printf '%s\n' "$demo_output"`. В нём откройте
`trial-1/summary.json`, результаты, проверки и `journal.md`.

Для одной роли поставьте `--roles 1`, для трёх `--roles 3`. Создавайте новую
временную папку для отдельной репетиции. Попытки не перезаписываются.

## Карточки испытаний

| Что показать | Вход и параметры | Ожидается |
|---|---|---|
| Второе пробное | `cases/trial-2.json`, `--attempt trial-2` | complete |
| Нет входа | `cases/missing.json`, `--attempt missing` | missing_input, результатов нет |
| Согласование | `cases/approval.json`, `--attempt waiting` | waiting_approval |
| Явное согласие | тот же вход, `--attempt approved --approved` | complete, manual_approval=true |
| Повтор события | `cases/trial-1.json`, `--attempt duplicate` | duplicate, повторной выдачи нет |
| Недоступность | `cases/trial-2.json`, новая папка, `--attempt offline --unavailable` | unavailable |
| Исправление раннего шага | `cases/trial-1.json`, `--attempt revision-2 --revision 2 --roles 3` | новые результаты всех трёх ролей |
| Новая версия согласуемого | `cases/approval.json`, `--attempt approval-v2 --revision 2` | снова waiting_approval |

Во всех командах сохраняются префикс `python3 week6/demo/simulator.py`, полный
путь `week6/demo/cases/...` и `--output "$demo_output"`.
Одобрение через CLI здесь лишь вход теста, не защищённый механизм согласования.
Симулятор однопроцессный; он не проверяет гонки, серверную безопасность и сетевые ретраи.

## Снимки до и после

`trial-1/` служит неизменяемым снимком до исправления, `revision-2/` снимком после.
Новая версия меняет все выходы и их контрольные суммы, следующие роли получают
ссылку на новый предыдущий результат. Это демонстрация зависимости, не ИИ-редактура.
Скрипт не удаляет папки и не копирует секреты: записывает только встроенные поля
вымышленного входа и учебные метаданные. Для настоящей записи отдельно подготовьте
копию своего демонстрационного проекта, без доступов и персональных данных.

## Что отдельно проверять живым запуском

- Настоящее исполнение ролей и изоляцию контекстов.
- Реальные API, браузер, зависимости, права, хранение ключей.
- Планировщик после закрытия сессии и перезагрузки сервера.
- Проверку источника согласования и устаревшего ответа.
- Параллельные события, таймауты, отсутствие повторных внешних действий.
- Перенос на VPS/Hermes и фактическое получение результата.

Если живая проверка не состоялась, в видео и отчёте пишите «не проверено».
